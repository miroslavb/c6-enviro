# C6 Enviro engineering rules

- Control-plane invariant (v0.1.13): never put writable settings on a manufacturer-specific custom cluster. `report_interval_s` uses EP1 `genAnalogOutput.presentValue`; `gas_enabled` uses EP1 `genOnOff` commands. Keep both at EP1 so acceptance remains `epList:[1,2,3,4,5]`; Z2M numeric controls can arrive as a scalar or `{value:N}`.
- Z2M deployment invariant: `biometal_enviro.mjs` imports only `enviro-contract.generated.mjs`, `enviro-defs.mjs`, and `enviro-defs.factory.mjs`. Never overwrite generic `lib/contract.generated.mjs` / `defs.mjs` in the shared external_converters directory.
- Sleepy-control timeout invariant: pass the cadence-aware `timeout` options returned by `sleepyControlWriteOptions(meta)` to **both** standard `ep.write` and `ep.command`. Herdsman's 10 s default races a sensor whose current interval is 10 s; use a 30 s minimum, current-interval + 10 s when larger, and a 120 s cap. At intervals above that cap, tell the user to RESET/BOOT into the bounded RX window rather than reporting a false device failure.
- Browser serial capture invariant: the public Web Serial console is local-only unless opened through an operator-issued short-lived `#capture=` capability. The fragment must be removed with `history.replaceState` before serial reads begin; uploads go only to `/flash/enviro/api/serial/v1/ingest` with a bearer header. Never embed a server token in static JS, query text, logs, or documentation. A saved browser `fetch` must be invoked as `fetchFn.call(globalThis, ...)`; calling it as a `SerialCapture` method throws `Illegal invocation` before the relay sees a request.
- Static deployment invariant: deploy `/var/www/c6-enviro` with directories mode `0755` and files mode `0644`; a root-owned `0600` JS module becomes a Caddy 403 even when the route is correct.
- LED colour is a bounded commissioning diagnostic, not a power-state oracle. Before treating it as a failure, check live Z2M `interviewCompleted`, `first_boot`, `status_flags`, and advancing `wake_count`.
- Timer-wake LED invariant: write `if (first_boot && led_init() == ESP_OK)`, never reverse the operands. C evaluates `&&` left-to-right; the old order initialized RMT/WS2812 on every deep-sleep wake despite the intended gate.

- Preserve the product role: ESP32-C6 **sleepy end device** powered from a solar-charged Li-ion cell. `rx_on_when_idle=false` is the normal and timer-wake state; v0.1.13 may set it true only during the scheduler-bounded `AWAKE_WINDOW_S` cold-boot/BOOT interview window, then explicitly restores false. Every normal timer wake uses a separate 1 s fast parent-poll control slot before telemetry, not continuous RX. Do not copy permanent-router behavior from the mains-powered sibling projects.
- Use `/root/c6-lcd-zigbee` and `/root/c6-radiometer` as differential controls for shared ESP32-C6 / ESP-IDF 5.4 / esp-zigbee-lib behavior, while treating router-vs-ZED power semantics as an intentional difference.
- Keep the arena acceptance oracle live: build/tests are supporting evidence only. Interview success requires Z2M `interviewCompleted:true`, `epList:[1,2,3,4,5]`, current `swBuildId`, and no active-endpoint timeout.
- v0.1.13 recovery identity is `0x8efd49fffe1a3d8c`; hardware acceptance must use this IEEE and must first show device-side `JOINED`, not merely Z2M `device_joined`.
- Routine browser flashes must preserve `zb_storage`: the erase-first checkbox defaults OFF and missing checkbox state fails safe to `eraseAll=false`; whole-flash erase is an explicit confirmed factory-new recovery step, never a default.
- Never force-remove, factory-reset, or erase the live device/network state without explicit user approval.
- Follow TDD for firmware behavior changes, then run host tests, contract parity, Z2M tests, Docker ESP-IDF 5.4 build, final manifest/version checks, and fresh final-file verification.
- A delayed reporting callback belongs to exactly one join attempt: cancel it on replacement or `LEAVE`, and treat `LEFT` as higher priority than a concurrently set `REPORTING_READY` bit.
- Normal-wake control invariant: standard downlink writes are parent-buffered, so timer wakes reserve `NORMAL_CONTROL_POLL_WINDOW_MS=1000` at 200 ms polls **before** telemetry/reporting. Restore `ED_KEEP_ALIVE_MS=1000` before reporting; never trade this for permanent RX. Live 2026-07-25 telemetry-through-timeouts proved that a 1 s normal poll without a distinct receive slot is insufficient.
- After any code change, update this file and the affected architecture/integration/lessons documentation before committing and pushing.
