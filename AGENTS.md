# C6 Enviro engineering rules

- Control-plane invariant (v0.1.14): never put writable settings on a manufacturer-specific custom cluster. `report_interval_s` uses EP1 `genAnalogOutput.presentValue`; `gas_enabled` uses EP1 `genOnOff` commands; EP1 also hosts the standard `genPollCtrl` server. Keep all three at EP1 so acceptance remains `epList:[1,2,3,4,5]`; Z2M numeric controls can arrive as a scalar or `{value:N}`.
- Z2M deployment invariant: `biometal_enviro.mjs` imports only `enviro-contract.generated.mjs`, `enviro-defs.mjs`, and `enviro-defs.factory.mjs`. Never overwrite generic `lib/contract.generated.mjs` / `defs.mjs` in the shared external_converters directory.
- Sleepy-control queue invariant: converter configure must bind EP1 `genPollCtrl` to `coordinatorEndpoint`; before every interactive control set/get, set Herdsman's `device.pendingRequestTimeout` from the cadence-aware 30–120 s budget and pass `sendPolicy:"bulk"`. The firmware emits one direct `genPollCtrl.checkin` on every normal timer wake and checks in through the binding every 10 s during the bounded cold-boot/BOOT awake window; Herdsman then answers `checkinRsp`, flushes pending requests in fast-poll mode, and sends `fastPollStop`. Never revert to an unsynchronised immediate write merely by increasing its timeout. Current Herdsman can log a tolerant default-response timeout for `fastPollStop`; accept only when the queued set/read succeeded, later telemetry persisted the value, subsequent CheckIns use `startFastPolling=0`, and cadence proves the device is not stuck fast-polling.
- Browser serial capture invariant: the public Web Serial console is local-only unless opened through an operator-issued short-lived `#capture=` capability. The fragment must be removed with `history.replaceState` before serial reads begin; uploads go only to `/flash/enviro/api/serial/v1/ingest` with a bearer header. Never embed a server token in static JS, query text, logs, or documentation. A saved browser `fetch` must be invoked as `fetchFn.call(globalThis, ...)`; calling it as a `SerialCapture` method throws `Illegal invocation` before the relay sees a request.
- Static deployment invariant: deploy `/var/www/c6-enviro` with directories mode `0755` and files mode `0644`; a root-owned `0600` JS module becomes a Caddy 403 even when the route is correct.
- LED colour is a bounded commissioning diagnostic, not a power-state oracle. Before treating it as a failure, check live Z2M `interviewCompleted`, `first_boot`, `status_flags`, and advancing `wake_count`.
- Timer-wake LED invariant: write `if (first_boot && led_init() == ESP_OK)`, never reverse the operands. C evaluates `&&` left-to-right; the old order initialized RMT/WS2812 on every deep-sleep wake despite the intended gate.
- Z2M recovery invariant: frontend `starting/unhealthy` is not enough to declare ZNP dead. If coordinator-version output plus valid advancing UNPI/SRSP/AF frames exist, stop restarting and let startup progress. A sleepy Enviro can serialize EP1–EP5 metadata reads; after monitoring is active, one non-erasing Enviro RESET may open its bounded RX window so those reads complete.
- Supervisor secret boundary: watchdog recovery uses the local authenticated Supervisor API and changes only the watchdog boolean. Never print full add-on `info/options` responses; they include MQTT credentials and Zigbee network material. Restore watchdog `true`, runtime/on-disk logging `info`, and verify live health after recovery.
- Acceptance evidence precedence: direct ZCL response and subsequent device telemetry/runtime state outrank lagging `database.db` attributes or stale `swBuildId`. Do not manually mutate the DB or repeat a proven control solely because its persistence snapshot has not caught up.

- Preserve the product role: ESP32-C6 **sleepy end device** powered from a solar-charged Li-ion cell. `rx_on_when_idle=false` is the normal and timer-wake state; v0.1.17 may set it true only during the scheduler-bounded `AWAKE_WINDOW_S` cold-boot/BOOT interview window, then explicitly restores false. Every normal timer wake sends standard Poll Control CheckIn and keeps the bounded 1 s fast-poll slot before telemetry, not continuous RX. Do not copy permanent-router behavior from the mains-powered sibling projects.
- Use `/root/c6-lcd-zigbee` and `/root/c6-radiometer` as differential controls for shared ESP32-C6 / ESP-IDF 5.4 / esp-zigbee-lib behavior, while treating router-vs-ZED power semantics as an intentional difference.
- Keep the arena acceptance oracle live: build/tests are supporting evidence only. Interview success requires Z2M `interviewCompleted:true`, `epList:[1,2,3,4,5]`, current `swBuildId`, and no active-endpoint timeout.
- v0.1.17 recovery identity is `0x8efd49fffe1a3d8c`; hardware acceptance must use this IEEE and must first show device-side `JOINED`, not merely Z2M `device_joined`.
- Routine browser flashes must preserve `zb_storage`: the erase-first checkbox defaults OFF and missing checkbox state fails safe to `eraseAll=false`; whole-flash erase is an explicit confirmed factory-new recovery step, never a default.
- Never force-remove, factory-reset, or erase the live device/network state without explicit user approval.
- Follow TDD for firmware behavior changes, then run host tests, contract parity, Z2M tests, Docker ESP-IDF 5.4 build, final manifest/version checks, and fresh final-file verification.
- A delayed reporting callback belongs to exactly one join attempt: cancel it on replacement or `LEAVE`, and treat `LEFT` as higher priority than a concurrently set `REPORTING_READY` bit.
- Reporting-settle/heartbeat invariant (v0.1.17 candidate): `esp_zb_zcl_update_reporting_info()` uses `REPORTING_MIN_INTERVAL_S=1`; a 900 s v0.1.16 no-erase soak proved that a `report_interval_s` maximum cannot heartbeat an unchanged value across reboot-per-wake deep sleep (T/RH refreshed while Pressure `last_reported` stayed stale). For every normal (`quiet=false`) wake, mirror current measurements into the ZCL backing store **before** registering slots, then use `cycle_reporting_wake_heartbeat_max_interval_s(REPORTING_MIN_INTERVAL_S)` (2 s) for both max fields so one standard unchanged-value report becomes due before the 2.2 s READY release. The device still wakes only at the persisted user cadence; cold/commissioning paths retain `cycle_reporting_max_interval_s(g_config.report_interval_s, ...)`. Never replace this with the empirically unsafe manual report API. Never emit `ZB_EVT_REPORTING_READY` synchronously; cancel both setup and ready alarms on replacement and `LEAVE`. Acceptance requires a no-erase soak with multiple source/HA T/RH/P transitions, including unchanged Pressure.
- Main lifecycle invariant (v0.1.15): `LEFT` during quiet/setup/settle means `REJOIN`, not retry sleep. Startup and mid-cycle recovery must both call `wait_for_network_and_reporting()`. Every `EVT_FIRST_JOIN`, including a timer-wake mid-cycle rejoin, reopens `AWAKE_WINDOW_S`; only a plain timer-wake `EVT_JOINED` restore remains short. A failed join/rejoin expires at `max(wait_start + CONFIG_ENVIRO_JOIN_TIMEOUT_S, s_awake_until_us)` so an active commissioning window is honored but a stale nonzero timestamp cannot disable battery protection.
- Current field-unit battery invariant: the 2×200 kΩ divider midpoint is not connected to GPIO2. Its ADC, `vbat_mv`, percentage, voltage, and `battery_low` values are floating and must not be used for diagnosis or acceptance until the wiring is repaired.
- Normal-wake control invariant: deep-sleep reboot can reattach through a different parent, so an arbitrary parent-buffered write is not a reliable queue. Timer wakes must send `genPollCtrl.checkin` to coordinator EP1 **before** `schedule_self_reporting()`, retain `NORMAL_CONTROL_POLL_WINDOW_MS=1000` at 200 ms polls, and restore `ED_KEEP_ALIVE_MS=1000` before reporting. Hardware acceptance requires a queued `report_interval_s` write to receive its ZCL response and appear in subsequent telemetry; telemetry alone is not proof.
- After any code change, update this file and the affected architecture/integration/lessons documentation before committing and pushing.
